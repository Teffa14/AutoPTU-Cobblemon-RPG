# Durable canonical item reservations

This slice makes canonical item-instance truth and active item reservations survive process restart without moving PTU item effects into Minecraft.

`FileCanonicalItemReservationRepository` stores one server-owned `CanonicalItemInstance` and at most one active `ItemReservation` in each atomically replaced item file. Item IDs are hashed with SHA-256 before they become filenames. Writes use an in-process lock, an OS file lock, `FileChannel.force(true)`, and required atomic replacement.

A reservation is created only when the stored item owner, template ID, quantity and revision still match the server-created reservation request. While a reservation is active, independent item revision replacement is rejected. Commit decrements quantity, advances the item revision exactly once and removes the reservation in the same atomic file replacement. Release removes only the reservation and preserves quantity/revision.

Because the reservation is stored with the canonical item record, a server restart does not silently forget a held quantity. A new repository instance can find the reservation and either commit or release it. Two repository instances racing on one item revision serialize through the same stable lock file, so only one active reservation can win.

The repository implements the existing `CanonicalAssetRepository` contract. Pokémon lookup is deliberately injected as a read-only dependency. This slice does not claim durable Pokémon persistence yet.

Authority boundary:

- client packets never create `CanonicalItemInstance` records;
- clients cannot supply trusted quantity, ownership, template identity or item revision;
- reservation IDs are server-generated by `CanonicalAssetService`/battle authority;
- Minecraft inventory stacks are presentation/input state only and do not become PTU inventory truth;
- commit/release changes resource ownership state only; item battle effects remain AutoPTU-Java-owned;
- no item ability, healing, capture modifier, damage hook, crafting rule or other PTU semantic is implemented here.

Compatibility dependencies for this slice are `ITEMS` (PARTIAL) and `MINECRAFT_COBBLEMON_CRAFTICS_ADAPTER_PLAYBACK` (PARTIAL). The store consumes only verified identity/quantity/revision reservation boundaries. It does not rely on any BLOCKING category.
