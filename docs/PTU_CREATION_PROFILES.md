# PTU creation profiles — 0.4.0-ptuprofiles1

This advances rule execution beyond the read-only sheet, but is not the full requested
PTU gameplay conversion. AutoPTU-Java calculates creation state; Cobblemon still resolves
native captures and battles.

## Executed in the core

- The complete 36-nature source CSV is bundled and checksummed as dataset 16.
- Python-compatible nature choice and ability tier choice at levels 1/20/40, including
  starting pools, duplicate handling, sparse-pool fallbacks and RNG consumption.
- Python CSV campaign minmax point allocation: level + 10 points, candidate builds,
  proportional HP floor, deterministic objective scoring and tie-breaking.
- Nature application after allocation, with a minimum stat of 1, matching the source
  generation-to-PokemonState order rather than assuming a different tabletop policy.
- Base maximum HP: level + 3 × HP stat + 10. Battle passives, injuries and temporary
  modifiers are not applied by this creation contract.

Core source: AutoPTU-Java PR #533, pin `ca7bb78abfd93ac608af4917033722698226e677`.
Its 3,600 frozen cases were generated by the actual Python functions at source revision
`16d228efa63aabecb67fa788959a359aac7f8f03`; source file hashes are included in that fixture.
All cases compare nature, allocation, final stats, base HP, selected abilities and next RNG word.

## Persistence and presentation

`autoptu:ptu_profile_v1` belongs to the same real Pokémon UUID. The server generates a
seed only when the key is absent, invokes the core and saves the immutable result with
species/catalog/core provenance. Loaded world Pokémon, party synchronization, native
starter/acquisition events and owned PC inspections use the same path.

The native starter preview still shows species bases only: it does not create a profile
or consume a creation seed before Cobblemon confirms and creates the actual Pokémon.

Reopening menus, changing native moves, swapping party/PC stores or loading a saved
profile never rerolls it. Corrupt, empty, null, wrong-schema and wrong-UUID records are
preserved rather than silently repaired. Changes to native species/form, level, catalog
or core revision display reconciliation status; they do not reset stats or restore HP.

Open **Ficha PTU** in Cobblemon's Summary/PC, or `/autoptu ptu party 1`. The profile section
shows saved PTU level/nature, base maximum HP, base + points + nature breakdowns, relative
stat bars and selected PTU abilities. The original native screen is retained.

## Deliberate boundaries

- Native identity/form and initial level establish the creation correspondence. Native
  IVs, EVs, stats, nature, HP and ability are not copied as PTU values.
- Only positively resolved level-up native move correspondences inform the initial
  minmax build profile. These are **allocation inputs**, not PTU move grants. No missing,
  tutor/egg/level-zero or above-level move is accepted as an allocation input.
- No independent PTU known-move loadout or battle/current-HP record is falsely created.
- Selected ability names are persisted; their combat handlers are not all connected.
- XP, training, custom point allocation, evolution reconciliation, injuries, capture
  accuracy/ball effects/trainer features and full native-menu PTU combat remain pending.
- This is the project's existing Python auto-build policy, not a claim of manual
  tabletop build validation or a generic Base Stat Relations implementation.

## Local verification

Core: `gradle test --tests '*PokemonCreationTest'` passes three tests including all 3,600 cases.
Adapter: 40 focused PTU/native tests pass, including profile JSON round trips, point/HP invariants,
one-time initialization, no rerolls, UUID mismatch, malformed state, species/level/catalog/core
changes, all 36 natures and preservation of the original native move/ability bindings.
This is not a graphical starter → battle → capture → save/restart acceptance test.

The installed previous mod is backed up outside `mods`; worlds and COBBLEVERSE are unchanged.
